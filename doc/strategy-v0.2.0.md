# v0.2.0：多层双边网格

标签：`v0.2.0`

## 核心逻辑

程序同时维护 BUY 和 SELL 两侧的多层限价单。层数由 `layers` 控制，每层数量使用配置中的 `quantity`。

第 `n` 层的振幅为：

```text
(2 × n - 1) × spread
```

例如 `spread = 0.02%`、`layers = 2`：

```text
BUY1 = 当前价 × (1 - 1A)
BUY2 = 当前价 × (1 - 3A)
SELL1 = 当前价 × (1 + 1A)
SELL2 = 当前价 × (1 + 3A)
```

订单标识包含层号：

```text
BOD1_<时间戳>
BOD2_<时间戳>
```

## 启动和恢复

启动时读取交易所当前 BOD 多层挂单，并从订单 ID 解析层号。当前挂单继续管理，不依赖旧订单名称以外的人工输入。

如果没有程序挂单，则以当前价格创建完整 BUY/SELL 网格。程序状态文件保存订单列表、层号、待配对成交和收益统计。

## 网格调整

每次检查会比较两侧当前程序挂单数量：

- 两侧数量相等且少于配置层数：重建完整网格。
- 一侧数量为 0：保留另一侧的 `layer 1`，取消其余高层订单，并按 `layer 1` 的振幅补单。
- 两侧都存在但数量不等：达到重校准间隔后，只重校准订单较多的一侧；每个订单继续使用自己的层号和振幅。
- 两侧数量完整：不调整。

默认成交检查间隔为 20 秒，价格重校准间隔为 600 秒。重校准会撤销目标侧订单并按当前价格重新创建同层订单。

## 收益

不能简单按订单相邻顺序配对，因为可能连续成交多笔 BUY 或多笔 SELL。程序分别保存：

```text
pending_buys
pending_sells
```

每次成交进入对应队列，然后按 FIFO 取最早 BUY 和最早 SELL 配对：

```text
收益 = (SELL 成交价 - BUY 成交价) × 配对数量
```

数量不一致时按较小数量配对，剩余数量留在队列。未配对成交不计入已实现收益。

## 特点

相对于单订单策略，多层订单可以在不同价格距离捕捉波动，降低价格移动后某个方向完全没有成交机会的问题。代价是同时管理多个订单和多笔未配对成交，状态恢复必须以订单 ID、层号和成交记录为依据。
