# v0.1.0：单订单反向挂单

标签：`v0.1.0`

## 核心逻辑

程序只管理 `clientOrderId` 以 `BOD_` 开头的订单，只针对 `ETHUSDC`。

程序启动时优先恢复自己的未完成订单：

1. 查询 ETHUSDC 当前未完成订单。
2. 只识别 `BOD_` 前缀订单，人类订单不撤销、不修改。
3. 没有自己的挂单时，查询当前净持仓；多仓挂 SELL，空仓挂 BUY，无仓使用初始方向。

运行中只有完整成交 `FILLED` 才会反向挂单：

```text
BUY 成交 -> 当前价格 × (1 + spread) 挂 SELL
SELL 成交 -> 当前价格 × (1 - spread) 挂 BUY
```

订单数量以实际完整成交数量为基础；后来调整为下一笔新订单使用配置文件当前的 `quantity`，当前已有订单不因配置改变而修改。

## 检查和重挂

- 默认每 20 秒检查订单状态。
- 默认每 600 秒重新校准挂单价格。
- BUY 只有新价格更接近市场时才撤单重挂，SELL 同理。
- 订单被人工撤销、过期或以其他非 `FILLED` 状态结束时，保留原方向，使用当前配置的完整数量重新挂单。
- `PARTIALLY_FILLED` 在挂单仍存在时继续等待；终态后按完整配置数量重挂。

## 收益

成交记录按相邻的 BUY/SELL 两笔配对，奇数笔最后一笔不计收益。`current_profit` 统计本次进程收益，程序启动时把上次当前收益并入 `total_profit` 后清零。

## 特点

这个版本每次只维护一个程序订单，逻辑简单，仓位变化容易理解，但价格长期移动时，反向单可能长期远离市场，成交机会下降。
